## Сообщение об уязвимости

**НЕ открывайте публичный GitHub Issue для уязвимостей безопасности.**

Сообщайте о них приватно через один из каналов:

- **GitHub Security Advisories**: [Сообщить об уязвимости](https://github.com/chen-xin-Liam/powerful-claw/security/advisories/new)
- **Email**: начните приватное обсуждение в репозитории с меткой `security`

### Что включить в отчёт

1. **Описание** — что за уязвимость и как она эксплуатируется
2. **Воздействие** — чего может добиться атакующий (утечка данных, выполнение кода, повышение привилегий и т.д.)
3. **Шаги воспроизведения** — минимальные шаги или proof-of-concept код
4. **Окружение** — ОС, версия Python, затронутые модули (ИИ-сервис, WebSocket, MCP и т.д.)
5. **Предлагаемое исправление** (опционально) — патч или идея митигации

### Чего ожидать

| Этап | Срок |
|------|------|
| Подтверждение получения | В течение 72 часов |
| Первичная оценка | В течение 7 дней |
| Исправление или митигация | Зависит от критичности (критичные — в приоритете) |
| Публичное раскрытие | После слияния исправления, с указанием автора (если не запрошена анонимность) |

## Модель безопасности

### Уровни разрешений

Приложение реализует **4-уровневую модель разрешений** для операций ИИ-агента:

| Уровень | Возможности |
|---------|-------------|
| **None** | Нет доступа к экрану, нет симуляции ввода |
| **View** | Только захват экрана, только чтение |
| **Limited** | Захват экрана + ограниченные клавиатура/мышь (исключая критичные области системы) |
| **Full** | Полный доступ к экрану + неограниченные клавиатура/мышь |

**По умолчанию**: `None` — операции агента запрещены до явного включения пользователем.

### Обработка данных

- **API-ключи** хранятся локально в `.env` или `config/settings.ini` и не передаются третьим лицам
- **Скриншоты** обрабатываются локально; отправляются настроенному ИИ-провайдеру только при запросе пользователя
- **История диалогов** хранится локально в `conversations.json` и исключена из контроля версий
- **Связь кластера LAN** использует симметричное шифрование Fernet (AES-128-CBC) с обменом ключами RSA

### Сетевые сервисы

| Порт | Сервис | Доступность |
|------|---------|-------------|
| 15000 | WebSocket (основной) | `0.0.0.0` — доступен в LAN |
| 15001 | WebSocket (вторичный) | `0.0.0.0` |
| 15002 | HTTP API сервер | `0.0.0.0` |
| 15003 | WebSocket (API) | `0.0.0.0` |
| 15004 | Монитор экрана | `0.0.0.0` |
| 15010 | Видеоредактор | `0.0.0.0` |
| 15012 | WebSocket видеоредактора | `0.0.0.0` |

**Примечание**: по умолчанию сервисы привязаны к `0.0.0.0` для работы в LAN. Если удалённый доступ не нужен, ограничьте их правилами файрвола.

### MCP-серверы

MCP-серверы запускаются как **локальные подпроцессы** с транспортом stdio. Они наследуют переменные окружения приложения, включая API-ключи. Импортируйте MCP-конфигурации только из доверенных источников.

## Известные замечания по безопасности

- **Автоматизация рабочего стола**: агент может симулировать ввод клавиатуры/мыши. Вредоносные промпты или скомпрометированный ИИ-провайдер могут вызвать нежелательные действия. По возможности используйте уровень `Limited`.
- **Захват экрана**: скриншоты могут содержать чувствительную информацию (пароли, личные данные). Приложение не фильтрует такое содержимое перед отправкой ИИ-провайдерам.
- **Непроверенные MCP-серверы**: импортированные MCP-серверы работают с теми же привилегиями, что и основное приложение. Проверяйте конфигурации перед импортом.
- **Без песочницы**: приложение работает с полными привилегиями пользователя в ОС. Будьте осторожны при включении режима `Full`.

## Рекомендации пользователям

1. **Используйте разрешения `View` или `Limited`**, если не нужна полная автоматизация
2. **Не выставляйте порты 15000–15012 в публичный интернет** — файрволом ограничьте доступ только LAN
3. **Не коммитьте API-ключи в контроль версий** — используйте `.env` (уже в `.gitignore`)
4. **Проверяйте MCP-конфигурации** перед импортом из внешних источников
5. **Регулярно обновляйте зависимости** — `pip install -U -r requirements.txt` для патчей безопасности

## Область действия

**В области** отчётов:

- Обход аутентификации/авторизации в модели разрешений
- Удалённое выполнение кода через сетевые сервисы
- Утечка API-ключей через логи или сетевой трафик
- Повышение привилегий при управлении MCP-серверами
- Доступ неавторизованных лиц к данным (скриншоты, история диалогов, API-ключи)

**Вне области**:

- Уязвимости сторонних зависимостей (сообщайте апстрим-проекту)
- Атаки с использованием социальной инженерии
- Физический доступ к машине
- Проблемы, требующие от пользователя отключения защиты (например, режим `Full`)
